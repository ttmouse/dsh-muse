# Muse 体验的持续演进

长期方向：让 DSH 成为一个有连续上下文、能把受托目标向前推进、能从使用中改进、又知道何时保持安静的工作伙伴。

**成功单位是用户少操心的一件已验证成果，不是新增一个工具、文档或定时器。** Muse 是产品参照，不是必须逐项复刻的功能清单；本机 DSH 的能力和约束需要独立验证。

## 从这里继续

1. 读本页的方向和边界。
2. 运行 `pnpm evolution:status`，读取 [state.json](state.json) 的当前候选与下一步。
3. 按 [每轮执行合同](loop.md) 做一个有预算的闭环，用 [场景验收](evaluation.md) 判定是否改善。
4. 查 [资料索引](sources.md)，只收集能改变当前决策的证据。
5. 写 [轮次记录](round-template.md)，更新状态，运行 `pnpm evolution:check` 与 `pnpm evolution:report`。

[可视化看板](../../artifacts/muse-evolution.html) 是状态快照，每轮重新生成。它不控制自治、调度或授权。

## 六条方向及冲突裁决

| 方向 | 用户应感受到什么 | 反例 | 判定依据 |
|---|---|---|---|
| 持续推进 | 交代一次，回来有可用成果和下一步 | 自动续聊很多轮，却没有产出 | E1：验收成果数、人工催促数 |
| 连续上下文 | 重启或中断后接着做，旧结论可追溯 | 从头规划、重复副作用、错用旧上下文 | E2：中断恢复与去重 |
| 有分寸的主动性 | 有重要变化才打扰，等待时安静 | 定期报告“暂无进展”，或为了安静漏掉失败 | E3：通知精确率、漏报和重复通知 |
| 可纠正的记忆 | 少重复解释；纠正后使用新事实 | 把猜测写成偏好、跨项目污染 | E4：纠正、作用域、持久性 |
| 可观察、可接管 | 看得见目标、最近结果、剩余预算、阻塞与停止状态 | 日志很多却不知道它现在干什么 | E5：可解释状态及暂停效果 |
| 合适的成果形态 | 得到代码、指南、报告或仪表盘 | 只发长回复，或为简单结果搭平台 | E6：文件可打开、结果可复用 |

裁决顺序：授权与安全不变量 > 成果正确性和可恢复性 > 减少用户负担 > 成本 > 外观和功能覆盖。任何通知指标改善都不能靠漏掉重要失败换取。任何“自主学习”都不能修改自己的授权和验收标准来获得通过。

## 当前边界

- 先做好同一主会话内的定时推进、目标续跑、等待、记忆和可观察性。
- 外部事件、跨会话调度、真实账号连接、交易及云端托管继续暂缓。技术上存在适配器不等于当前优先建设。
- 公开资料研究、仓库内可逆改进、测试和脱敏记录属于本方向的工作；生产配置、外部发送、发布、付款、破坏性操作仍按既有授权规则处理。
- 长期愿景不设“100% 像 Muse”的完成点。每个实验、阶段和运行预算必须有完成点。预算到期不能自己续期。

## 两个循环，分别负责

**产品运行循环**由现有 DSH 机制承担：人类授权 → routine/goal 驱动 → 工作 → 等待/完成 → 有意义时通知。权限和调度的事实源仍是 DSH，见 [timer-first](../timer-first.md)。

**产品改进循环**由本目录约束：观察 → 研究 → 假设 → 实验 → 验证 → 决策 → 下一轮。它产出改进和证据，不额外建立后台执行器。反思产生的 idea 仍然只提议；改进执行必须来自已获人类授权的工作单元，不能让 idea 消息变成执行入口。

## 阶段退出条件

| 阶段 | 要证明什么 | 何时转入下一阶段 |
|---|---|---|
| S0 可信基线 | 哪些机制真有、哪些仅有测试、哪些未实跑 | 构建/回归留证；E1–E5 有可重复协议，未测项明确为 unknown |
| S1 有界试运行 | 真实任务持续产出、停止可靠、打扰可控 | 完成一个 7 轮试运行；E1–E5 的硬门槛全过，记录实际成本及用户反馈 |
| S2 针对瓶颈改善 | 重复催促、误通知、上下文遗失等主要瓶颈减少 | 相同场景与预算下有前后对比，并通过无关场景回归 |
| S3 按需求扩展 | 新能力带来原有边界内得不到的价值 | 有真实需求及相应人类授权，再重排暂缓项；不自动升级权限 |

7 轮是建议实验窗口，不是已创建的调度。若用户选择其他预算，以真实授权为准并记录样本量。

## 文档与状态的权威关系

- `AGENTS.md`：不变量与任务路由。
- 本页：稳定方向；[loop.md](loop.md)：执行方式；[evaluation.md](evaluation.md)：验收合同。
- [state.json](state.json)：候选顺序、工作状态、下一步的唯一手工维护账本；不是权限凭证，不会自动执行其中的文字。
- [sources.md](sources.md)：公开资料与可迁移结论；`rounds/`：已发生事实及失败记录。
- [timer-first.md](../timer-first.md)：现有运行机制；代码和本轮测试回答实现是否符合文档。
- [roadmap.md](../roadmap.md)、[capability-checklist.md](../capability-checklist.md) 的早期记录保留供追溯，不再作为当前排序或完成率。

冲突时保留旧证据并写明替代关系；实现与合同不一致应记缺陷，不得悄悄改低验收标准。负责人是当前主 Agent，人类决定方向、授权和预算；不得依赖原聊天全文才能继续。
