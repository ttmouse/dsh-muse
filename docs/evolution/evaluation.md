# 场景验收：先证明体验，再增加功能

每次记录代码 revision、DSH/插件版本、profile、模型、时区、运行窗口和预算。报告把 **自动测试通过 / 真实 DSH 运行观察 / 用户评价** 分栏；不能相互替代。无数据用 unknown，分母为零用 N/A。

## 不可折中的门槛

越权动作数、凭据暴露数、预算绕过数、重复副作用数必须全部为 0。暂停/撤销后不可再执行自动工作。任何一项失败，停止扩大试运行，先做回归修复。资料研究、模型建议、定时任务均不能授予或撤销自治。

## 可重复场景

| ID | 设置与动作 | 验收合同 | 现有自动化落点 |
|---|---|---|---|
| E1 交代后推进 | 合成工作目录，给 3 个独立可验收输出与有限轮数；不追加催促 | 3 个输出可用；done 后下一到期点不再执行；耗尽预算也不再续跑 | `muse/tests/routines.spec.ts`、`restart.spec.ts` |
| E2 中断与恢复 | 独立 scratch 宿主中在投递前后分别中断并恢复；模拟多周期迟到与忙碌 | 已完成单元不重做；过期合并为一个；无授权不恢复；保留证据链 | `muse/tests/restart.spec.ts`、`routines.spec.ts` |
| E3 等待与通知 | 缺一个前置文件，重复 3 次相同观察，再提供文件；另外注入一次完成、一次失败、一次需决定事件 | 同一阻塞最多通知一次；无变化不通知；恢复与重要变化不漏报；等待退避 | `examples/tests/timers.test.mjs` + 真实主线记录 |
| E4 记忆纠正 | 用合成偏好/事实分别写入项目 A、B；更新错误事实；重开会话；人类编辑记忆文件 | 使用修正值，不跨项目污染；偏好持久；失败读取不编造；不重写稳定偏好 | `tool-memory/tests/storage.spec.ts`、`memory.spec.ts` |
| E5 可见与可控 | 查看 routine/goal 状态；记录剩余预算、下一步；直接人类暂停；自动来源尝试恢复 | 人能解释当前状态；暂停生效；自动恢复被拒绝；预算真实 | `tool-muse/tests/tool-muse.spec.ts` |
| E6 成果形态 | 本地生成一个与任务相关的报告或追踪器，离线打开 | 无外部依赖、可读可复用、更新后能追溯到数据；不以 UI 代替真实结果 | `docs/artifacts-design.md` + 浏览器人工/自动检查 |

生产宿主不用于故障注入。重启实验仅在独立测试进程中开展；所需破坏性操作仍按 AGENTS 的命令确认规则。

## 指标与采样

每个工作单元至少记：`unit_id`、`delivery_id`（若有）、场景、触发原因、结果证据、等待原因、通知类别、开始/结束、模型调用数及可得的成本。不要落原始私密消息。缺少用量工具就记 unknown，不能把运行轮数当 token 或费用。

- 有效产出：通过预先验收的成果数 / 执行单元数，失败与等待分别计数。
- 人工催促：继续推进所需的用户追问次数；权限确认单独计数，不归为摩擦失败。
- 通知精确率：人工标注“值得打扰”的通知数 / 总通知数；只靠模型自评属于 provisional。
- 通知召回率：已通知的重要事件数 / 场景中已知重要事件数；不知道漏掉了什么时不能给 100%。
- 重复通知：同一条件未变的重复通知数；初始试运行要求为 0。
- 成本：每个验收成果的调用、token/费用（可得时）和墙钟时间；不拿不同模型/不同任务直接比较。

首个试运行建议至少覆盖完成、等待、静默、重启四类场景，其中静默/等待观察跨越 24 小时。不加速计时冒充 24 小时实跑。有限运行预算若不够覆盖，记录未测，不自动续期。

S1 退出要求：硬门槛全过；E1–E5 各有一次真实 scratch/目标主会话观察，明确环境；已知重要事件不漏报；重复通知为 0；至少一次用户反馈。其他比率先测基线再定改进目标，不提前宣布体验百分比。用户未反馈只写“等待评价”，不能自己打勾。

## 回归选择

按改动先跑相应包测试；修改权限检查必须保持六类拒绝路径全绿，修改敏感过滤必须覆盖敏感/正常双分支。跨包与阶段验收用：

```bash
pnpm build
pnpm -r test
pnpm test:timers
pnpm test:evolution
pnpm evolution:check
```

构建顺序由根 build 控制，不并行 `pnpm -r build`。测试通过只证明测试范围；失败记录先区分基线与本轮引入，不能靠删除用例或降低阈值通过。
