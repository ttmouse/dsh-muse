# R-多工作者-串行化发现

- 日期：2026-10-05 ｜ 类型：真实场景发现（B06 并发演示）
- 现象：3 个工作者会话同时派生（12:43），5 分钟后全部未开工（每会话仅 1 条 user 事件、0 条 agent 回复）；而更早的单独工作者（12:38）1 分钟内完成交付。
- 根因：桌面宿主串行推进会话；主会话 goal 轮次持续运行时，其他会话的队列不启动。
- 结论：**「多目标并发」当前的真实形态是「透明排队、交错执行」**，不是真并行。与 Muse 的差距：其云端宿主可并行推进多目标。
- 解除条件（真并行）：工作者会话运行在独立宿主进程（detached host runner），如 launchd 托管的每工作者一个 headless dsh 实例。
- 过渡语义（已可用）：工作者透明排队，主会话空闲时按序执行——对用户的可见效果仍是「主控汇报结果」，只是完成时间拉长。
