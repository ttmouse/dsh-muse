# R-B02-prompt-parity · 判断门与评估器 prompt 一致性

- 日期 / 检查时刻：2026-10-05 13:29 Asia/Shanghai
- 候选：B02 → waiting
- 执行者：主 Agent 单写；纯合成输入，不读取真实消息或决策日志
- 授权：当前 Codex 目标授权仓库内可逆改进与合成样本评估；不外发真实内容
- 实验成本上限：最多 15 次 `deepseek-chat` 调用（10 条有标签样本 + 5 条边界样本）；不得输出或记录凭据内容，调用失败即停止

## 观察与假设

- 基线观察：`examples/gate/notify-eval.mjs` 声称使用与 gate 相同的 prompt，但其 prompt 额外列出 marketing 拒绝条件，运行时 `gate.mjs` 没有。这使既有 10/10 合成准确率不能证明当前运行时 prompt 的结果。
- 假设：让 gate 和评估器导入同一个 prompt 常量，可以消除 prompt 漂移；按同一评估器重放 15 条合成样本能得到可复现的当前模型快照，但不能证明真实通知的体验价值。
- 通过条件：运行时与评估器使用同一常量；15 条合成样本评估完成并记录输出、precision/recall 与调用数；结果仅标为 provisional。
- 不通过条件：prompt 仍有副本、judge 输出无法解析，或任何非合成内容进入评估输入。
- 回退办法：恢复本轮新增共享常量并还原两个调用点；既有判断门运行逻辑不变。

## 结果与判定

- 新增 `examples/gate/notification-judge-prompt.mjs` 作为单一 prompt 来源；运行时 gate 和合成评估器现在导入同一常量。
- 命令：`node examples/gate/notify-eval.mjs`；退出码 0；合成模型调用 15 次，完成于 2026-10-05 13:29–13:30 Asia/Shanghai。
- 有标签样本：9/10 与实现者标签一致；precision 100%（5/5），recall 83%（5/6），重复通知 0。唯一未命中为“例行周会 30 分钟后开始”。
- 边界样本：3 say / 2 skip，只记录模型输出，不计准确率。
- 旧的 10/10 结果不能与本轮直接比较：旧评估 prompt 和 gate prompt 不同，且标签未独立复核。
- 结论：inconclusive。单源 prompt 修复完成；单次合成复测暴露一条标签争议，但不能据此判断误报/漏报或调宽规则。真实消息、用户评价、模型稳定性仍 unknown。
- 下一步：等待独立人工标注，重点确认“30 分钟后开始的例会”是否应该打断；不调整 prompt 迎合这组标签。期间切换到 B04，盘点现有运行状态入口是否能回答当前工作、等待原因和剩余预算。
