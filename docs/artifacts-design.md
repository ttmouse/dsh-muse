# A3 Artifacts 设计（切片 1：设计定稿 + 最小实现路径）

Muse 能力清单 A3：**为任务生成可交互的定制界面**（开支追踪、学习指南、仪表盘）。这是清单里剩余最大的一项，本设计把它切成可自主推进的切片。

## Muse 的本质（从官方复盘提炼）

> 「让一个人帮你规划旅行，你想要的是一份行程单，不是一篇两千字的回复。如果你想长期追踪支出，比起每天一条消息，可能更想要一个实时更新的仪表盘。」

核心：**产出物的形态跟着任务走**，聊天文本只是其中一种。Muse 称之为 Artifacts——chat 之外更丰富、量身定制的内容。

## dsh-muse 的实现哲学：不建平台，用文件

Muse 有专属渲染管线（云端应用内嵌）。我们不走这条路——**HTML 文件就是最好的 Artifacts 载体**：

- agent 生成自包含 HTML（内联 CSS/JS，无外部依赖）写入项目或指定目录
- 用户双击/浏览器打开即用，可长期保存在本地
- 更新 = 重写文件（或数据 JSON + 固定壳 HTML 分离，更新数据不动壳）
- 零新基础设施，与现有 gate/reflect/goal 体系零耦合

## 切片规划

### 切片 1：约定 + 生成规范（本轮）
- 目录约定：`<项目>/artifacts/`（或用户指定目录）
- 生成规范写入 AGENTS.md 路由：当任务产出适合可视化/交互呈现时，agent 主动生成自包含 HTML Artifacts 而非长文本
- 模板起点：仪表盘（读 JSON 数据 + 图表）、追踪器（表单 + localStorage）、行程单/学习指南（静态富排版）

### 切片 2：数据驱动的活仪表盘
- 壳 HTML + `data.json` 分离；gate/reflect 心跳可更新 data.json → 打开即最新（「实时更新的仪表盘」的本地版）
- 无服务端：数据更新由巡逻写入，浏览器端 fetch 本地文件

### 切片 3：与提醒联动
- 仪表盘异常指标 → gate 规则引用 → 主动汇报（连接器语义复用）

## 与安全红线的关系

Artifacts 是**本地文件产出**，不涉及出站；生成内容中的外部数据引用须遵守 F3（不含凭证材料）。交互表单的数据仅存 localStorage，不上传。

## 验收标准（对标 Muse）

- [ ] 开支追踪仪表盘：给定支出 JSON → 生成可筛选/汇总的交互页面
- [ ] 学习指南：给定主题 → 生成可勾选进度的指南页
- [ ] 数据更新后（data.json 变更）刷新页面即见最新，壳不变
- [ ] 以上全部为自包含本地文件，无外部请求
